#5 - Admin Panel — UX & Reliability Fixes
What & Why
The admin panel audit found issues that make daily use unreliable: a 401 response (e.g. from a background request) immediately redirects mid-form without warning, the image upload silently ignores unexpected API response shapes, the CSV export is vulnerable to injection, and CRUD forms use uncontrolled refs making them error-prone to validate and reset. These fixes make the admin experience robust and trustworthy.

Done looks like
A 401 on a background API call shows a non-disruptive "Session expired — please log in again" toast/banner instead of instantly redirecting and discarding unsaved form data; only interactive navigation triggers a hard redirect
Image upload displays a clear error message when the API returns an unexpected response shape instead of silently setting an undefined URL
CSV export escapes values that start with =, +, -, @ to prevent spreadsheet injection
Channel / movie / series create & edit forms use controlled inputs (React state or react-hook-form) so validation feedback is immediate and reset-on-cancel works reliably
Bulk delete shows a progress indicator and reports partial failures per item instead of a single end-of-batch alert
Out of scope
Replacing output: "export" with a server-rendered build (requires hosting change)
Admin authentication redesign
Adding new admin pages or features
Steps
Fix axios 401 redirect UX — In lib/axios-client.ts, replace the immediate window.location redirect on 401 with a toast/banner notification and a grace period; only redirect if the user triggers a new navigation after the session expires.
Harden image upload response handling — In components/ui/image-upload.tsx, explicitly validate that the response contains a URL string and show an inline error if not, instead of silently accepting undefined.
Fix CSV injection in subscription export — In app/(admin)/subscriptions/page.tsx, prefix values starting with =, +, -, @ with a tab character (standard spreadsheet injection mitigation) before building the CSV string.
Convert CRUD forms to controlled inputs — In the channels, movies, and series create/edit modals, replace useRef form inputs with controlled useState or react-hook-form so validation runs on change and the form resets cleanly on cancel.
Add bulk-delete progress indicator — In app/(admin)/channels/page.tsx, show a progress bar or item count during bulk deletion and collect per-item errors to display a summary instead of one generic alert.

Plan #4 - API server — security & performance fixes
#4 - API Server — Security & Performance Fixes
What & Why
The API server audit found several issues that affect security and reliability: the YouTube stream-extraction endpoint has no auth guard (anyone can call it without a token), key search fields (channel name, movie/series title) have no database indexes so search slows down as content grows, the M3u import health-check hammers the database with one query per channel instead of batching, and the BullMQ consumer has no top-level error catch so unexpected errors crash the worker. Fixing these improves security, search speed, and import reliability.

Done looks like
POST /youtube/extract requires a valid JWT — unauthenticated callers get 401
Searching channels, movies, and series is fast even with thousands of records (indexes added on name/title and primaryStreamUrl)
M3u import health-check runs in batches (bulk fetch + bulk update) instead of 4 DB calls per channel — importing 1 000 channels no longer causes thousands of round-trips
BullMQ consumer wraps job processing in a try-catch so any unexpected error marks the job as failed cleanly instead of crashing the worker process
Out of scope
Migrating refresh tokens to hashed storage (separate security hardening task)
Redis-based rate limiting (existing OTP approach is acceptable for now)
Advertisement provider loop (low traffic, medium priority)
Steps
Add JwtAuthGuard to YouTube controller — Apply @UseGuards(JwtAuthGuard) to youtube.controller.ts so the extract endpoint is protected.
Add DB indexes for search fields — Add @@index([name]) on Channel, @@index([title]) on Movie and Series, and @@index([primaryStreamUrl]) on Channel in prisma/schema.prisma, then generate a migration.
Batch M3u health-check DB calls — Refactor processHealthCheck in m3u-import.service.ts to bulk-fetch all target channels in one query, run validations concurrently, then bulk-update results in one updateMany / $transaction instead of 4 calls per channel.
Wrap BullMQ consumer in try-catch — In m3u-import.consumer.ts, wrap the processImportJob call in a try/catch that logs the error and lets BullMQ mark the job as failed rather than crashing the worker.

Plan #5 - Admin panel — UX & reliability fixes
#5 - Admin Panel — UX & Reliability Fixes
What & Why
The admin panel audit found issues that make daily use unreliable: a 401 response (e.g. from a background request) immediately redirects mid-form without warning, the image upload silently ignores unexpected API response shapes, the CSV export is vulnerable to injection, and CRUD forms use uncontrolled refs making them error-prone to validate and reset. These fixes make the admin experience robust and trustworthy.

Done looks like
A 401 on a background API call shows a non-disruptive "Session expired — please log in again" toast/banner instead of instantly redirecting and discarding unsaved form data; only interactive navigation triggers a hard redirect
Image upload displays a clear error message when the API returns an unexpected response shape instead of silently setting an undefined URL
CSV export escapes values that start with =, +, -, @ to prevent spreadsheet injection
Channel / movie / series create & edit forms use controlled inputs (React state or react-hook-form) so validation feedback is immediate and reset-on-cancel works reliably
Bulk delete shows a progress indicator and reports partial failures per item instead of a single end-of-batch alert
Out of scope
Replacing output: "export" with a server-rendered build (requires hosting change)
Admin authentication redesign
Adding new admin pages or features
Steps
Fix axios 401 redirect UX — In lib/axios-client.ts, replace the immediate window.location redirect on 401 with a toast/banner notification and a grace period; only redirect if the user triggers a new navigation after the session expires.
Harden image upload response handling — In components/ui/image-upload.tsx, explicitly validate that the response contains a URL string and show an inline error if not, instead of silently accepting undefined.
Fix CSV injection in subscription export — In app/(admin)/subscriptions/page.tsx, prefix values starting with =, +, -, @ with a tab character (standard spreadsheet injection mitigation) before building the CSV string.
Convert CRUD forms to controlled inputs — In the channels, movies, and series create/edit modals, replace useRef form inputs with controlled useState or react-hook-form so validation runs on change and the form resets cleanly on cancel.
Add bulk-delete progress indicator — In app/(admin)/channels/page.tsx, show a progress bar or item count during bulk deletion and collect per-item errors to display a summary instead of one generic alert.

Plan #3 - Mobile app — fix critical UX bugs
#3 - Mobile App — Critical Bug Fixes
What & Why
Full audit of the Expo mobile app revealed several bugs that directly hurt user experience: API calls after a 401 are silently dropped, Live TV category tabs show empty lists, the live player gives vague error messages, the profile avatar button does nothing, and the notifications screen uses fragile string-matching logic. Fixing these makes the app feel polished and reliable.

Done looks like
POST/PATCH/DELETE requests that fail with a 401 are retried automatically after token refresh (same as GET already does) — no silent data loss
Live TV category tabs (Sports, News, etc.) correctly filter all channels across all pages, not just the first loaded batch — no more empty tabs
Live player shows a clear, specific error message when a stream is unavailable (distinguishes network error vs. subscription/permission issue)
Profile screen "Edit Profile" flow works end-to-end (name/email update); the placeholder avatar edit button is either wired up or removed
Notifications use the backend type field (or a stable identifier) for icon/category mapping instead of fragile title substring matching
Splash screen correctly distinguishes a network error from an invalid token, so a brief offline moment doesn't log the user out
Out of scope
Push notification setup / FCM integration
Redesigning any screens visually
New features (favorites, watch-later, etc.)
Steps
Fix token refresh retry for all HTTP methods — In lib/api.ts, extend the 401 interceptor to re-attempt the original request for all methods (POST, PATCH, DELETE, PUT) after a successful token refresh, not just safe methods.
Fix Live TV category filter — In app/(main)/live-tv.tsx, fetch ALL channels (or use server-side category filter param) before applying the tab filter so selecting "Sports" doesn't show an empty list just because that page isn't loaded yet.
Improve live player error messages — In app/live-player/[id].tsx, distinguish 403/subscription errors from generic network errors and surface a human-readable message with a retry or upgrade CTA.
Fix profile avatar button + profile edit — In app/(main)/profile.tsx, wire the Edit Avatar button to an image picker or remove it, and ensure the profile edit form (name, email) submits to the correct API endpoint.
Fix notifications type mapping — In app/notifications.tsx, use the notification's type field from the API response (instead of .includes('match') title hacks) for icon and category assignment.
Fix splash screen network-error handling — In app/(auth)/splash.tsx, treat non-401 errors as a network failure (show retry UI) instead of redirecting the user to login.
